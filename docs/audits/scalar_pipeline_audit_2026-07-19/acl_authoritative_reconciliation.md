# ACL v1 Authoritative Reconciliation

## Conclusion

The selected ScenarioNet core already permits no mutation: ACL v1 §23.3 defines `mab_plus_replay` with MAB, scenario buffer, replay, usefulness-plus-staleness sampling, and `use_mutation: false`; ScenarioNet v1.1 §2.6 additionally freezes scenario mutation as disabled. The six ScenarioNet arms are governed by the more specific ScenarioNet v1.1 §22.5 contract (`K=6`). Therefore neither mutation exclusion nor A0–A5 requires an ACL v1.1 rewrite.

The material §11 conflict is resolved by the approved ACL v1 §28 and ADR-014. For the selected core, `ScenarioUsefulness.value` depends only on learning potential; Rulebook fields are diagnostic-only, and mutation remains prohibited. This is not a transition-replay change and not a full ACL v1.1 rewrite.

Repository evidence: no `C_safe` identifier was found in production ACL code, configuration, tests, or frozen manifests. `rule_criticality` and `dominant_rule` remain diagnostic fields in `src/thesis_rl/curriculum/scenario_acl/usefulness.py`; the numeric `value` equals `learning_potential`. ACL §12 PPO/TD3/SAC calculators are now implemented and propagated by custom and SB3 planner backends; GPU runtime verification remains pending.

## Approved Narrow Amendment Contents

ACL v1 §28 and ADR-014 define `ScenarioUsefulness.value = LP_alg_s`; state that `C_safe`, Rulebook margins, criticality, safety ranks, and Rulebook-derived fields are not ranking, replacement, replay-probability, or MAB-feedback inputs; permit diagnostic-only Rulebook fields without changing value; preserve MAB, Generate/Exploit, replay, warm-up, capacity, replacement, and staleness; prohibit mutation and child creation under ScenarioNet v1.1; and specify state migration/restart for existing ACL artifacts.

It must not change the approved transition-replay v1.0 `n_steps` domain or introduce five-step behavior.
